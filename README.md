# Лабораторна робота №5: Обробка помилок, файли та серіалізація

**Тема:** Розробка надійного модуля імпорту, експорту та конфігурації даних для системи банківських рахунків (Варіант 4).

**Автор:** Войтович Максим Андрійович (група ФеП-31).

## Опис проєкту

Проєкт реалізує надійний пайплайн для обробки даних утиліти банківських рахунків. Основна мета роботи — забезпечити стійкість програми до винятків, коректну роботу з файловими ресурсами через `pathlib` і контекст-менеджери, потокову обробку даних (`streaming I/O`), валідацію зовнішніх даних та захист вихідних файлів за допомогою атомарного запису (`atomic write`).

## Основні можливості

- **Ієрархія кастомних винятків:** власні класи помилок (`ApplicationError`, `DataImportError`, `RecordValidationError`, `ConfigurationError`, `DataExportError`) із підтримкою `exception chaining` (`from error`).
- **Конфігурація через YAML:** завантаження та валідація налаштувань із зовнішнього файлу `config.yaml` з використанням безпечного `yaml.safe_load()`.
- **Потоковий імпорт (Streaming I/O):** читання великих CSV-файлів за допомогою генераторів (`Iterator`) без повного завантаження в оперативну пам'ять.
- **Гнучка політика обробки помилок:** підтримка режимів `strict` (зупинка на першій помилці) та `tolerant` (пропуск і логування некоректних рядків зі збереженням статистики).
- **Валідація бізнес-правил (Варіант 4):** перевірка номерів рахунків, клієнтів, невід'ємного балансу, дозволених операцій (`deposit` / `withdraw`), сум транзакцій та захист від появи від'ємного балансу.
- **Безпечне логування:** використання модуля `logging` із захистом від потрапляння конфіденційних даних у логи та автоматичним додаванням `traceback` для критичних помилок.
- **Атомарний експорт:** запис результатів у JSON через тимчасові файли (`.tmp`) із наступною атомарною замінкою, що запобігає пошкодженню даних при аварійному завершенні програми.
- **Власний контекст-менеджер:** вимірювання часу виконання операцій за допомогою генераторного контекст-менеджера (`@contextmanager`).
